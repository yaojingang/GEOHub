# One-line SEO Method

Start with the business outcome, market, language, surface, target inventory, time window, available evidence, and permitted action. Select one mode: advisory, technical audit, keyword-to-page map, incident, migration, experiment, international/commerce, or implementation request.

The deterministic runtime creates a scoped plan and leaves `findings` empty. An implementation request becomes write-authorized only when its brief also carries at least one target URL, explicit implementation authorization, and a non-empty rollback boundary.

Evaluate in dependency order: access and discovery; fetch and rendering; index eligibility; canonical and alternate signals; technical delivery; page meaning and intent; internal architecture; specialty surfaces; measurement. A small URL sample must keep its coverage visible.

Evidence labels are `observed`, `inferred`, and `missing evidence`. Impact and confidence stay separate. Search Console and analytics exports are first-party evidence; current official provider documentation governs mutable platform rules; public pages and third-party estimates keep their date and scope.

For keywords, map intent and expected page type before clustering. Leave search volume and difficulty `unknown` without named dated data. For incidents, segment pages, queries, markets, devices, search types, and time before testing competing explanations. For migrations and implementation, record before evidence, rollback, verification, and platform-processing lag.

Keep robots access, index directives, canonical preference, sitemaps, structured-data syntax, search-feature eligibility, lab performance, field performance, deployment, platform processing, and observed outcomes as distinct layers.

This method draws structural inspiration from the MIT-licensed Qiaomu SEO project; GEO SEO Hub uses its own schemas, runtime, routing, evidence contracts, and AGPL distribution boundary.
