What GEOHub already does exceptionally well

六项能力已经达到很高的工程标准

这些能力值得保留为系统约束。引入任何外部框架时，都要继续满足现有的确定性、诚实降级和回放边界。

01

证据缺口从不被悄悄补齐

provided、observed、inferred、source_gap 和 blocked-by-evidence 贯穿输出。排名缺少同口径矩阵时直接停止生成结果。

02

Artifact Bus 的发布语义很稳

同文件系统暂存、完整文件集校验、manifest 对账、最终原子 rename，失败运行不会暴露半成品目录。

03

诊断输入安全做得很深

显式 URL、公共地址校验、DNS 和连接预算、重定向复验、媒体类型与字节上限、无跟随文件读取均有测试覆盖。

04

Skill 包轻量且边界清楚

四个 SKILL.md 合计约 5 KB，详细方法下沉到 references，执行下沉到 scripts，符合渐进加载的方向。

05

不可用能力会诚实返回 planned

strategy、knowledge、publish、measure 保留清晰的最近可用能力和所需输入，没有把 roadmap 包装成现成功能。

06

发布与安装验证超过多数早期 Skill

8 个包可重复构建、fresh venv 安装模拟、多 Python 版本、跨 OpenAI、Claude、generic 适配器，形成了可审计的发布面。

Recommended decomposition

把 GEOHub 拆成四个平面、十五个可独立演进的模块

拆分以稳定契约为边界。每个模块拥有输入、输出、评测和回滚边界，GEOHub 继续承担套件级注册、路由、编排和发布。

控制平面

决定调用谁、按什么顺序执行、何时暂停。

  • geo-registry所有能力、owner、版本、依赖、状态
  • geo-router规则优先 + 语义影子路由 + abstain
  • geo-workflow状态图、checkpoint、人工确认、恢复

可信平面

统一输入、证据、产物、安全和供应链边界。

  • geo-contracts类型模型与生成 Schema
  • geo-artifactsrun index、diff、resume、export
  • geo-evidencesource → claim → decision → output 谱系
  • geo-securityURL policy、文件边界、权限与威胁模型

智能平面

决定 GEOHub 能否产出真正有竞争力的结果。

  • geo-discovery模板、HyDE、问题生成、聚类、去重
  • geo-auditgatherer、audit、score、custom audits
  • geo-content研究、提纲、成稿、证据、人工评审
  • geo-optimize候选生成、引擎评价、fidelity、memory
  • geo-knowledge实体关系、community、local/global query

质量平面

  • geo-observabilitytrace、cost、quality、drift、adoption
  • geo-releaseSBOM、provenance、sign、verify

90-day upgrade path

先补效果证据，再升级算法，最后扩展知识与规模

顺序来自依赖关系。没有真实评测，算法升级无法判断收益；没有运行谱系，优化循环无法复盘；没有采用数据，Library 成熟度无法长期维持。

0-30 DAYS · P0

建立可信基线

  1. 用真实输出替换 expectation-level blind pack，接入 Inspect 风格 task、solver、scorer。
  2. 增加 provider-backed GEO benchmark，固定 query、source、engine、prompt、时间与成本。
  3. 加入 Ragas 风格 claim faithfulness、answer relevance 和 citation support 指标。
  4. 为 route、skill、artifact、eval 增加隐私安全的 OpenTelemetry spans。
升级门槛：至少 5 个真实 GEO 任务、2 个模型、2 个引擎、20 组盲评，公开失败分类。
31-60 DAYS · P0/P1

升级领域算法

  1. 发现链路加入模板基线、HyDE、问题生成、聚类和新颖度评测。
  2. 诊断链路改为 Lighthouse 式 gatherer、audit、score、report 四层。
  3. 内容链路增加 STORM 式 research、outline、draft、polish，可保留纯离线 profile。
  4. 排名链路增加 MCDA 规范化、criteria polarity、敏感性和不确定性分析。
升级门槛：真实任务质量相对 0.2.0 提升，成本、时延和事实性均有记录，边界用例无回归。
61-90 DAYS · P1/P2

形成学习循环

  1. 引入 MAGEO 式 preference、planner、editor、evaluator、fidelity、memory 主循环。
  2. 工作流升级为可 checkpoint、恢复、人工确认的状态图。
  3. 建立 GraphRAG 式品牌事实与实体关系层，支持 local 和 global 查询。
  4. 发布加入 SLSA provenance、SBOM、签名与第三方验证。
升级门槛：策略可复用收益、回归风险、知识更新成本和供应链验证均可复现。

Borrow the mechanism, preserve the boundary

六条借鉴边界，防止把 GEOHub 做重

这些世界级项目覆盖面很广。GEOHub 只借能提高可靠性或效果证据的机制，继续保留当前的离线、确定性和诚实降级优势。

语义路由先跑影子模式

保留词法路由作为安全权威。语义层只记录候选、置信度和分歧，达到 holdout 门槛后再参与决策。

LangGraph 只服务动态长流程

单步 discover、diagnose、content 继续用当前 CLI。需要暂停、恢复、人工确认和多分支时才进入状态图。

STORM 分成 offline 和 research 两个 profile

纯证据包继续离线执行。联网研究必须显式授权，并记录检索器、查询、来源快照和时间。

GraphRAG 从品牌事实卡起步

先验证实体去重、关系证据和增量更新，再决定是否引入昂贵的 community summarization。

观测数据只留元数据

默认记录 skill_id、run_id、时延、状态、错误类型、artifact digest 和质量分。客户内容、URL 与证据正文保持本地。

科学评分必须保留原始分量

GEO visibility、faithfulness、authority、cost 和 latency 分开记录。聚合分可用于排序，原始指标负责复核。

Primary sources and audit method

19 个一手来源，评分与事实分开

仓库、论文和标准均链接到原始来源。GitHub stars 为 2026-08-12 API 快照，只表示社区触达范围。报告中的成熟度分数属于专家判断。

审计方法：先检查本地架构、Skill、运行时代码、Schema、测试、评测和发布报告，再把能力拆成控制、可信、智能、质量四类。每个要素选择一个方法最贴近、公开证据充分的对标对象。

主要限制：GEOHub 当前没有 provider-backed 模型运行、真实 AI 平台测量、已完成的人类盲评和采用遥测。报告把这些项保留为 missing evidence。所有数字判断都带有日期和证据范围。
