01 · 定位

一个面向 GEO 工作流的能力操作系统

它把用户自然语言请求转成最小可执行 Skill 或稳定工作流，再把每次执行固化为带证据状态、质量报告和运行清单的目录

GEOHub 把自然语言请求拆成五类能力入口：发现、诊断、内容、测量、一句话 SEO，统一入口负责识别意图，Research Kernel 约束科学边界，Artifact Bus 负责交付和复现

GEO 与 SEO 共享查询、证据、实体、内容和站点结构能力，独立 seo Provider 负责技术审计、关键词页面映射、Search Console 事故、迁移与实验规划

Planned：strategy、knowledge、publish3

01

Registry 驱动

技能状态、意图、入口和输出由单一注册表声明，Router 从注册表编译 Action 与 Intent Index

02

确定性执行

输入经严格 Schema、长度和文件边界验证，相同有效输入生成稳定结构，避免隐式网络研究

03

证据可追溯

事实结论连接 evidence ID，缺失来源保留为 unverified、source_gap 或 blocked-by-evidence

04

科研边界

54 篇论文与 2 个数据集汇总为 11 条运行原则，明确相关、基准、因果与治理状态

05

原子交付

完整文件集在隐藏 staging 目录生成并校验，成功后一次发布，失败不会留下半成品 run

06

显式降级

可选 DOCX/PDF 失败时保留 Markdown、JSON 与 HTML，Manifest 记录缺失依赖和 renderer error

02 · 架构

请求经过五层，最终成为可审计运行记录

架构将自然语言选择、确定性执行、研究约束和交付协议分开，每层职责独立，公共数据结构保持兼容

选择层保持轻量路由器只返回技能、状态、入口和可选执行图，执行逻辑保留在能力提供者内部
执行层各自封装发现、诊断、内容、测量与搜索优化拥有独立输入合同和输出规范
公共层保证兼容证据账本、研究上下文、质量报告与运行清单提供跨技能对接界面
03 · 路由

Router 先判断可用性边界，再选择最小执行单元

输入会先经过字符与字节预算、Unicode 归一化、引用区间识别和否定作用域解析，planned 能力始终保持不可执行

  1. 输入预检上限为 8,000 字符和 16,384 UTF-8 字节，超限返回确定性验证错误
  2. 单次语义预计算引用区间、连接词、否定范围、Action Index 与 Intent Index 每个请求只扫描一次
  3. planned 优先保护命中 strategy、knowledge 或 publish 时返回 required_inputs、closest artifact 和 nearest active
  4. 精确工作流匹配只有 Registry 声明的阶段组合与顺序才生成 DAG，说明文字中的后缀意图不会误触发
  5. 最小 active Skill单一目标直接路由到 discover、diagnose、content、measure 或 seo，宽泛请求回到 geo

04 · 能力

六个 active Skill 覆盖 GEO 工作流与一句话 SEO

每个 Skill 都能独立安装和执行，也能通过 geo Router 选择最小入口，下表展示输入、核心处理和主要输出

geo

ACTIVE · ROUTER
统一入口与能力状态面处理宽泛 GEO 请求、单能力选择、planned 状态和两个稳定 DAG
INPUT
中英文自然语言请求
OUTPUT
skill_id、status、runnable、entry、reason、suggestion、workflow

geo-discover

ACTIVE · OFFLINE
把词根和业务主题扩展为问题簇与机会图固定生成 learn、compare、evaluate、act 四种任务形态，去重并保留父查询血缘
INPUT
subject、seed_queries、audience、scenario、evidence
OUTPUT
query-map、opportunity-map、evidence-ledger、research-context

geo-diagnose

ACTIVE · BOUNDED NET
诊断品牌、站点或单页的 GEO 准备度分析 title、description、canonical、heading、FAQ、JSON-LD、可抽取结构和证据信号
INPUT
显式 URL、HTML 快照或 evidence，scope 为 brand / site / page
OUTPUT
diagnosis、funnel、report、remediation query-map、opportunity-map

geo-content

ACTIVE · 7 MODES
从结构化 brief 与证据生成可追溯内容先构建 mode 对象，再派生 content-spec、typed Markdown、escaped HTML 和 evidence units
INPUT
topic、mode、brand facts、evidence、可选 source content
OUTPUT
content-spec、content、evidence units、Markdown、HTML、可选 DOCX/PDF

geo-measure

ACTIVE · OFFLINE
汇总用户提供的 AI 平台观察记录保留合格试验、缺失回答、排除原因、平台分层和 Wilson 区间，统一标记 descriptive
INPUT
query、engine、interface、locale、timestamp、answer 与 citation 状态
OUTPUT
answer rate、citation rate、conditional rate、interval、platform strata

seo

ACTIVE · OFFLINE PLAN
把一句自然语言 SEO 需求转成证据约束的执行计划识别技术审计、关键词页面映射、流量事故、迁移、实验、国际化、电商和实施请求，保留缺失证据与授权边界
INPUT
request、target URLs、market、language、authorization、rollback、evidence
OUTPUT
seo-plan、report、evidence-ledger、quality-report、run-manifest
01 / title标题多样候选、意图与合规评分，清除无证据绝对词和生成年份
02 / explainer解释型内容定义、原因、步骤、选择标准、误区、FAQ 与来源
03 / comparison中立对比要求完整 entity × dimension 证据矩阵，缺口阻断结论
04 / ranking方法榜单要求完整分数矩阵和透明方法，不完整时不输出排名
05 / page-blueprint页面蓝图信息架构、摘要、FAQ、表格、Schema 候选和验收项
06 / refine内容优化保留源文事实，记录前后分数与修改说明，不新增数据
07 / article-friendly文章适配复用 refine 合同，增加发布型 Markdown、证据标记和风险提示
05 · 场景

当前版本覆盖十四类 GEO 与 SEO 任务

场景按 Registry、两条稳定 DAG、七种 Content mode 和一句话 SEO 工作模式汇总，每个场景都能追溯到一个 active 入口或明确 planned 状态

geo-diagnose

品牌全景诊断

检查 identity、offering、audience、differentiation、proof 和 contact 事实覆盖

交付：品牌级 findings + remediation
geo-diagnose

网站与单页审计

检查可发现性、结构、可抽取性、证据、权威与新鲜度代理信号

交付：diagnosis funnel + HTML snapshot
geo-content

标题与解释型文章

生成合规标题、定义边界、操作步骤、误区、FAQ 与来源段

交付：content.md + content.html
geo-content

产品对比与榜单

按同口径证据或完整评分矩阵生成中立对比和方法透明的排名

交付：matrix gaps 或有证据结论
geo-content

页面信息架构

设计摘要、FAQ、表格、语义 HTML、Schema 候选、CMS 字段和验收清单

交付：page blueprint + acceptance checks
geo-content

已有内容优化

保留源文事实边界，调整结构和表达，未链接事实继续保持 unverified

交付：before / after + change notes
geo-measure

AI 回答与引用测量

汇总回答率、引用率、条件引用率、缺失答案、排除理由与不确定区间

交付：measurement-report.json
seo

一句话 SEO 规划

从自然语言需求识别技术审计、关键词页面映射、国际化、电商或实验模式

交付：seo-plan + evidence gaps
seo

流量事故与迁移控制

08 · 研究

56 个来源被压缩成11 条运行原则

研究仓库固定提交中的 54 篇论文与 2 个数据集经过逐项审计，运行时读取精简 Registry，并为每次执行生成 research-context.json

效果声明需要直接测量准备度、可见度和 influence score 都属于代理变量
查询多样性保持条件化用于规划覆盖，不能推断需求量或转化
诊断分数只表达 readiness评分不会变成平台引用概率
语义相关优先于格式战术内容保真和证据连接拥有更稳健支持
对比要求同口径证据矩阵不完整时保留缺口，不输出胜者
榜单需要操纵防护透明方法、完整分数与威胁模型共同约束
结构编辑必须可逆结构可能改善也可能退化，需要前后记录
测量必须保留分母重复试验、缺失回答、区间和平台范围同时报告
知识需要溯源与冲突控制权利、时效、冲突与投毒风险进入治理边界
SEO 与 GEO 共享上游检索边界查询和证据可复用，SERP 与流量指标独立处理
发布需要授权与可逆性公开变更必须具备权限、预览、记录和回滚
研究边界：当前材料支持规划假设、描述测量和治理控制。它们无法为跨平台引用、排名、流量、转化或收入提供通用保证。详细审计见 geo-citation-lab-alignment-audit.md，机器矩阵见 research-evidence-matrix.json
